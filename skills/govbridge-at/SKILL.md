# GovBridge AT

Help the user run an OEGK search and interpret the extension's accumulated observations. Respond in the user's language. OEGK is the first supported service; do not imply support for other authorities.

Choose the workflow from the user's intent. Run Guided search only for a requested website search. For an explicitly stored-data summary or a single known claim ID, discover the read-only tools on an already supported page and obtain scoped consent; do not require a date range or initiate a new search. Do not imply that this read refreshes data.

## Boundaries and consent

- Use external Chrome with GovBridge AT. Read the available Chrome skill and its current runtime documentation before browser actions; discover the installed runtime instead of hardcoding plugin versions, paths, browser IDs, or remembered tab IDs. Do not substitute the in-app browser. If the user explicitly requests a different browser, explain this workflow's Chrome requirement and ask before switching.
- Leave ID Austria login, credentials, MFA, and consent screens entirely to the user. Ask them to sign in in Chrome and tell you when ready; do not inspect authentication fields, cookies, tokens, hidden JSF state, or browser/extension storage.
- Before any sensitive query-tool result or claim-bearing DOM/screenshot enters context, explain that it can contain personal, medical, and financial data and obtain consent for the intended scope. `list_claims` returns **all stored observations**, possibly from outside the requested period; disclose this before requesting consent for that tool. A narrow-period request alone is not consent to read the whole store. Reuse consent only within its agreed scope.
- An explicit user request for a website search, including its requested dates, authorizes the bounded `search_claims` submission. Do not add a second skill-level approval prompt for that action. This pre-approval does not authorize reading sensitive claim results; obtain the separate scoped consent below. Honor any unavoidable confirmation required by the selected browser capability and never bypass it.
- Before consent, limit inspection to non-sensitive URL, capability metadata, and narrowly selected structural state. Avoid full-page snapshots, raw HTML, alert dumps, or screenshots that could reveal claims. If a safe structural check is unavailable, ask the user to describe the state. On refusal, offer navigation-only guidance and do not read claims.
- Do not file, edit, delete, or submit a reimbursement claim, open claim details automatically, or invoke/download PDFs. The only supported submission is the bounded **search form** action below. Do not export or persist personal results unless separately requested.

## Guided search

1. Resolve the user's inclusive `from` and `to` calendar dates as `YYYY-MM-DD`. Treat the maximum accepted query span as **five calendar years minus one day**. For a relative request such as “last 5 years,” use the user's timezone and compute `to = today` and `from = addCalendarYears(to, -5) + 1 calendar day`; when the anniversary falls on February 29, clamp it to February 28 before adding the day. Show the exact computed dates to the user before searching. For explicit user-provided dates, do not silently alter, clamp, narrow, or split them; pass them through and let server validation decide, then report any rejection. Ask about missing or ambiguous bounds. Same-day queries are valid.
2. Reuse or select a current Chrome tab and navigate to the MeineSV OEGK entry page `https://www.meinesv.at/vsInfo/views/KE/?contentid=10007.815943`. This is the search-mask entry point; MeineSV may redirect it to `/vsInfo/views/KE/einreichungTyp.xhtml`. Leave ID Austria authentication entirely to the user.
3. Perform at most one minimal preflight before invoking a tool. Use only the current URL, page title, exact presence of the heading `Einreichungen abfragen`, and the exact selected state of `Wahlarzt / Wahltherapeut`. Do not take DOM snapshots, run broad text searches, inspect raw HTML, or use screenshots. Do not use Playwright locators for this preflight; if no WebMCP-capable page state exposes the category selection and the category is not already selected, use one exact locator solely to select `Wahlarzt / Wahltherapeut`, then do not repeat the preflight. A missing or ambiguous heading/category is a wrong-page blocker.
4. Prefer the browser's native WebMCP tool surface and page navigation exclusively. Inspect the callable tools and live schema there; do not infer callability from hidden hints, diagnostics, or static metadata. The type/range page must expose `search_claims` with exactly required `from` and `to` ISO-date fields before proceeding. If native WebMCP is advertised but that tool/schema is absent, stop and report the capability mismatch; do not fall back to DOM automation.
5. Use CDP only when the browser advertises CDP but does not advertise native WebMCP, and only to inspect or invoke `document.modelContext`. Do not use CDP for snapshots, broad DOM inspection, or custom form automation. If neither native WebMCP nor CDP is advertised, report the missing capability.
6. Once `search_claims({from, to})` is exposed with the expected schema, invoke it directly once through that tool surface; the explicit website-search request is the skill-level authorization. The extension sets the actual website dates and submits `Weiter` or the retained results-form `OK`; do not fill dates or click either submitter yourself, call site functions, replay JSF requests, or construct form submissions. This action returns no claims. If it is unavailable, stop the automated search and offer user-operated search guidance; do not substitute scraping or raw storage access for any missing tool.
7. Treat `{ok:true,data:{status:"submission_requested"}}` as **dispatch requested**, not successful results or fresh storage. Navigation can legitimately return `null` or destroy the execution context. Verify the resulting page by navigation state and narrowly selected known result/validation markers only; do not repeat the preflight, take a snapshot, or resubmit after `null`, a timeout, lost context, or `SEARCH_IN_PROGRESS`. Explain uncertainty and obtain the user's direction before retrying. Cancellation cannot undo a dispatched click.
8. Confirm website state separately from stored data. The result route is `/vsInfo/views/KE/einreichungListe.xhtml`, headed `Liste der Einreichungen`; recognized groups are `offene Einreichungen`, `abgelehnte Einreichungen`, and `erstattete Einreichungen`. A documented empty-state alert contains `In diesem Abfragezeitraum wurde keine Kostenerstattung bzw. kein Onlineantrag gefunden.` A validation alert headed `ACHTUNG: Fehlerhafte Eingaben im Formular` is an error, not empty results. Read only those known, exact state markers before consent; never use broad page text as a substitute. Login, loading, unfamiliar, partial, or ambiguous state does not establish successful search or completeness.
9. An explicit empty-result alert can appear after full navigation back to the type/range route. This was live-verified; remaining on that route alone does not establish failure. The passive adapter does not commit that type-page alert as an empty stored snapshot. Report website emptiness separately from retained history.
10. After consent, query only the normalized data needed below. A tool read does not trigger extraction or refresh. If the passive observation may still be pending, allow one bounded recheck of safe state and, within consent, the relevant read-only query; do not rerun the search. Report any remaining observation/freshness uncertainty instead of polling indefinitely.

## Missing browser capabilities

- If Chrome is unavailable, use the Chrome skill's documented connection/startup troubleshooting and report the actual blocker. Do not conflate a stopped browser with a missing GovBridge AT extension.
- If native WebMCP is unavailable but CDP is advertised, use the documented CDP path only for `document.modelContext`; if that object or the expected tool is missing, verify the supported route and installed extension build. Advise reloading the existing unpacked extension from `dist/` and the page, then rediscover once; do not claim a reload fixed it without checking.
- If neither native WebMCP nor CDP is advertised, explain that this connection cannot invoke page tools. `pageAssets`, DOM hints, snapshots, and broad text searches are insufficient. Ask the user to connect the supported browser integration; do not modify browser security settings silently.
- On wrong-page or unavailable-form errors, navigate back to the verified selected query form rather than broadening selectors or submitting another category. Explain unsupported layout if the expected controls still cannot be confirmed.

## Query tools and interpretation

Use the live schemas. Existing query contracts are:

| Tool | Input | Meaning |
| --- | --- | --- |
| `list_claims` | `{}` | All validated stored claims; no date filter or implicit refresh. |
| `get_open_claims` | `{}` | Stored `submitted` or `processing` claims; excludes `unknown` and is not period-filtered. |
| `get_claim` | `{claimId}` | One canonical ID, obtained from consented data or supplied by the user; not a row index. |
| `get_reimbursement_summary` | `{year}` | Integer 2000–2100; totals for known `invoiceDate` values in that year, with known-amount counts and EUR currency. |

Successful queries use `{ok:true,data:...}`; failures use `{ok:false,error:{code,message}}`. Respect `INVALID_INPUT`, `NOT_FOUND`, `STORAGE_UNAVAILABLE`, and `INTERNAL_ERROR` without inventing results or falling back to page scraping. Search additionally uses `UNSUPPORTED_PAGE`, `FORM_UNAVAILABLE`, and `SEARCH_IN_PROGRESS`; a preflight rejection is not a completed search.

- Separate **the confirmed website search outcome for the requested bounds** from **the stored-claim summary**. Accumulated records may predate the search, lie outside its bounds, or include earlier detail enrichment. An empty website result does not erase stored history, and an empty store does not prove that the website had no results.
- `lastSeen` is observation time only. It proves neither membership in the latest query nor freshness of every field. Do not use it as a filter for the website period or claim that all records were refreshed just because their timestamps changed.
- Distinguish invoice, treatment, submission, and reimbursement dates. The site's query-period date semantics and unlabeled result dates are not established; do not guess them. An invoice-year summary is not equivalent to the website query period. Label any user-requested local date filtering by its exact canonical field.
- Optional missing amounts and dates are unknown, not zero. Totals include only known amounts; report the corresponding known counts when coverage is incomplete. Do not interpret invoice total minus reimbursements as confirmed outstanding debt or entitlement.
- Claim tools are read-only; `search_claims` has a write hint because it submits the search form. These annotations do not guarantee authorization or safety. Skill-level consent is not enforced by the extension's page-world bridge, whose messages can be observed or raced by page scripts; do not claim isolation from the host page.
