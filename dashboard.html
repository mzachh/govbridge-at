GovBridge AT

A WebMCP bridge for Austrian government services. The OEGK integration reads claims on demand from the currently rendered Meine SV page and does not retain claim records.

  • 3 live query tools + 1 bounded search action
  • Current page only
  • No claim persistence
  • No claim submissions

Data boundary

Live, page-scoped reads

Every query invokes the isolated live reader for the current document. No claim snapshot, observation history, or browser storage is created by this extension.

  1. 1Meine SV DOMrendered current page
  2. 2Live readerisolated extraction
  3. 3WebMCP bridgeMAIN-world proxy tools

Only canonical Claim fields and page metadata cross the closed bridge. IDs combine a document nonce, a snapshot digest, and row position; they are temporary and expire when the page changes. completeness: "partial" and skippedCount identify malformed rows without exposing page diagnostics.

PoC boundary: The current page is not refreshed, paginated, or merged with another page. “Live” means read at invocation time, not newly fetched server data. Displayed ranges do not prove server-query boundaries.

Workflow

Prerequisites and troubleshooting

  • For production, complete ID Austria login yourself and open a supported Meine SV OEGK route.
  • After search_claims, inspect the resulting page and rediscover tools. Its acknowledgement does not prove that the search succeeded.
  • If tools are unavailable, reload the unpacked extension and the Meine SV tab, then inspect native WebMCP or the local compatibility runtime. Hints alone do not prove callability.
  • For an expired ID or a changed page, call list_claims again. A plain search mask or unsettled navigation returns PAGE_NOT_READY.

The separate local simulator contains 20 invented claims for 2021-09-03–2026-09-02. It uses these same extension tools, not a separate fixture API. It is not MeineSV or OEGK.
